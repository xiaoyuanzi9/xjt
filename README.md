# 寻机头（Find Chicken Head）— 项目说明

> 双人对战策略游戏 + AI 引擎 + AI 技术检定工具。
> 本文档面向下一个接手的开发者（人类或 AI），涵盖游戏规则、使用方式、代码结构与已知注意事项。

**🎮 在线试玩：<https://xiaoyuanzi9.github.io/-/>**
（GitHub Pages 托管，随 main 分支推送自动部署更新；双击本地 `gamescode/index.html` 离线可玩）

## 1. 这是什么

「寻机头」是一款类似海战棋（Battleship）的推理游戏：双方各在 10×10 的方格场上秘密布置
3 架飞机（飞机由若干"机身"格和 1 个"机头"格组成，可旋转），随后轮流攻击对方格子，
根据反馈（0=空地 / 1=机身 / 2=机头）推理对方机头位置。先找齐对方全部 3 个机头者获胜。

本仓库包含：

| 内容 | 位置 |
|---|---|
| 游戏本体（双人 + 人机 + 自定义机队） | `gamescode/index.html` |
| AI 技术检定（独立工具，测试 AI 推理能力） | `gamescode/aicheck.html` |
| 联机对战（房间码 PvP，net.js + PeerJS） | `gamescode/net.js` |

## 2. 游戏规则

### 2.1 基本规则（经典模式）

- 场地为 **10×10** 方格（列 a–j，行 1–10）。双方各秘密布置 **3 架飞机**：
  - 经典机队 = 2 架 A 型 + 1 架 B 型（形状见机库缩略图，均为 1 个机头 + 若干机身，可旋转）；
  - 机头与机身不得出界、飞机之间不得重叠，其余格子为空（0）。
- 双方轮流攻击对方一个格子，攻击方获知该格内容：**0 = 空地 / 1 = 机身 / 2 = 机头**。
- 先找齐对方全部 **3 个机头** 的一方获胜。
- 特殊规则：若**先手**先找齐，**后手可再走一步**；此后双方步数相同则**平局**，
  否则先手获胜。（后手先找齐则直接获胜，无补走。）

### 2.2 伪装机头模式（可选规则）

在经典规则基础上改变反馈语义：

- 攻击空地：显示 0。
- 攻击到飞机（**无论机身还是机头**）：一律显示 **1** —— 机头会"伪装"成机身。
- **复查**：再次攻击一个显示 1 的格子以揭示真相——
  - 是机头 → 改显示 **2**（计入已找到机头）；
  - 是真机身 → 保持显示 1，但格子变为**暗金色**样式以示区分（内部值记为 3，仅程序使用）。
- 每次攻击（含复查）都计一步。其余胜负规则同经典模式。

> 界面约定：玩家可见的数字只有 0、1、2，"已确认的真机身"以变色的 1 呈现；
> 伪装模式下攻击"必然为机身/必然为空"的格子是纯浪费（不缩信念、不中机头），
> 这也是 AI 选格时排除它们的理论依据。

### 2.3 决定先后手

游戏内固定"玩家 1 / 你"为先手。

## 3. 程序使用方式

**无需安装任何东西**：直接双击 `gamescode/index.html` 用浏览器（Chrome/Edge）打开即可，
不需要本地服务器；也可以直接打开线上地址 <https://xiaoyuanzi9.github.io/-/> 游玩。

### 3.1 主页面（index.html）

开始画面为**三个切换按钮 + 【▶ 开始游戏】/【🌐 联机对战】**（按钮文字即当前选择，点按循环切换）：

1. **📜 规则**：经典规则 ⇄ 伪装机头（下方规则说明框随之切换）。
2. **👥 模式**：双人对战 ⇄ 人机对战。
3. **第三行按钮随模式变化**：
   - 双人模式：✈️ **机队**——经典机队 ⇄ 自定义机队。点按立即切换按钮文字并打开
     5×5 编辑器分别编辑 **3 架飞机**（每架恰好 1 个机头 + 至少 1 格机身）；
     确认样式后生效，返回开始画面即可开局；点回"经典机队"则放弃自定义。
   - 人机模式：⚙ **难度**——EASY ⇄ NORMAL ⇄ HARD ⇄ LUNATIC。
4. **▶ 开始游戏**：按当前选择开局。
   - 自定义机队暂不支持人机对战：模式为人机 + 机队为自定义时，开始键禁用
     （悬停提示原因）；自定义机队构建失败（如组合数超上限）时确认键保持可用
     以便调整重试，点"返回"会恢复到之前生效的机队选择。

**布置阶段**：进入时场地为空。点选机库中的飞机 → 鼠标移入棋盘预览（绿=可放/红=不可放）
→ 点击放置（点击格是机型"锚点"= 包围盒中心，镂空机型锚点格允许被占用）；
**点击已放置飞机的机头**移除整架飞机；R 键旋转；"💡 灵感"尝试把未放置的飞机随机摆上
（放不下则无事发生）；三架都放好后"✅ 确认布局"。

**对战阶段**：左为玩家 1 场地、右为玩家 2/AI 场地，点击对方场地格子即开火，
格上显示 0/1/2（及伪装模式的变色 1）。右上角 **？** 按钮弹出当前机队样式与本局规则说明。
状态栏显示双方已找到机头数与步数。

**结算**：获胜（或平局）后展示双方真实布阵与全部攻击痕迹，可"再来一局"。

### 3.2 AI 技术检定（aicheck.html，独立程序）

用途：检验 AI 的推理能力。AI 把你当作"真实布阵"来提问，你如实作答；
若你的回答自相矛盾，AI 会宣布"无解"。

- 模式页为**同一行的三个切换按钮 + 下一行的【▶ 开始检定】**（按钮文字即当前选择，
  点按循环切换；机队改动未确认前开始键禁用）：
  - 规则按钮：经典规则 ⇄ 伪装机头（按钮始终带"规则："前缀）；
  - 策略按钮：期望计算（=游戏内 hard 的高精度版）⇄ 贪心（=normal）⇄ 兜底（minimax）；
  - 机队按钮：经典机队 ⇄ 自定义机队（点按立即显示"自定义机队"并打开 5×5 三机编辑器；
    三架均合法并确认成功后开始键才可用）。
- 开始前可在棋盘上**预填数字**构造局面（伪装模式可填 0/1/2/3，3=确认真机身）。
- 开始后 AI 逐格提问，你按当前规则如实作答；状态栏实时显示剩余可能布局数。
- AI 找齐 3 个机头 = 检定成功；回答自相矛盾 = AI 宣布无解。
- **🄻 L 挑战**：单人挑战模式，与【▶ 开始检定】同行。点击后固定使用**经典机队**
  （忽略机队选择，不可自定义）并以 **LUNATIC 难度**出数字：由**玩家点击棋盘格子攻击**，
  LUNATIC 给出显示数字（伪装规则下首击 0/1、复查 2/3）；找齐 3 个机头即挑战成功，
  结束后展示一种与全部回答一致的布阵以及玩家所用步数。中途可"结束挑战并返回"，
  返回后自动恢复挑战前所选的机队。

### 3.3 联机对战（net.js + PeerJS）

纯静态实现的异地 PvP：信令用 PeerJS 公共服务器（jsDelivr CDN 引入），握手后攻击/答复
走两浏览器间的 WebRTC 直连，**双方真实布阵永不出本机**——只互传攻击坐标与显示值，
天然防作弊。人机/检定等离线玩法不受影响；联机仅支持双人对战。

流程：

1. 开始画面点【🌐 联机对战】→ 选择 **创建房间（房主）** 或 **加入房间（访客）**。
2. 房主获得 6 位房间码，发给对方；访客输入房间码加入。
3. 房主可随时调整：📜 规则（经典/伪装）、✈️ 机队（经典/自定义，形状会连同设置
   发给访客）、⏱ 每步限时（默认不限时，可开 60 秒）、🎯 先后手（默认我先手）；
   设置变更实时同步到访客界面。
4. 访客可查看当前规则说明与机队样式，点【✅ 准备】；访客准备后房主的
   【▶ 开始对战】解锁。
5. 双方各自秘密布置 → 都确认后自动开战（按房主选定的先后手）。
6. 开启限时后，轮到谁攻击谁的一侧开始倒计时，**超时自动随机攻击一格**。
7. 结算时双方互换真实布阵展示；【再来一局】回到联机大厅（连接保持），
   需重新准备后再开局。

## 4. 代码结构（gamescode/）

纯静态 HTML/JS/CSS，无构建步骤、无框架（唯一外部依赖：联机的 PeerJS 走 CDN）。

| 文件 | 职责 |
|---|---|
| `index.html` | 主页面结构（开始/交接/布置/对战/结算 5 个画面）+ 引入脚本 |
| `style.css` | 全部样式（画面切换靠 `.screen.active`） |
| `game.js` | 游戏状态与流程：布置（锚点放置/旋转/移除/灵感）、对战反馈、胜负判定（含先手补走/平局）、伪装模式反馈语义、自定义机队编辑器、帮助弹窗 |
| `ai.js` | AI 引擎：机队组合枚举、信念过滤、三种攻击策略、期望/最坏步数推演、LUNATIC"说谎"策略 |
| `aicheck.html` | 独立的 AI 检定工具（自带 ai.js 的运行环境垫片） |
| `net.js` | 联机大厅 UI + PeerJS 连接与消息分发（仅 index.html 引入，在 game.js 之后加载） |

**加载顺序约定**：index.html 中 `ai.js` 在 `game.js` **之前**（ai.js 无加载期依赖，
game.js 末尾调用 `buildEngine(PLANES)` 构建引擎）；其后依次加载 PeerJS CDN 与
`net.js`（联机大厅/连接，仅 index.html 引入）。aicheck.html 自带一份
SIZE/SHAPE/rotateShape 等垫片后再加载 ai.js —— 两处形状定义需人工保持一致。

### 4.1 关键概念与函数（ai.js）

- **组合（combo）**：一种完整的"三机布阵"。机队确定后，所有合法组合一次性枚举存入
  `comboStore`（Int32Array，每组合 3 个摆法下标），总数 `NCOMBOS`（经典机队 = 109,192）。
  `buildEngine(fleet)` 负责构建，可随时用新机队重建（自定义机队的入口）。
- **信念（atkArr/atkCount）**：AI 依据全部攻击观察过滤后的候选组合集合，
  用 `partitionBy` 就地划分。`syncAtk` 把 `guesses[1]` 中新观察应用进信念；
  伪装模式同一格会被问两次（首击 1、复查 2/3），因此以 `atkObs` 记录每格已应用的
  观察值，**观察值变化就重新过滤**（不要用"每格只处理一次"的集合，复查结果会丢失）。
- **策略入口 `aiChooseAttack()`**：按 `aiLevel` 分发。
  - easy：从未确定的格子中随机选一（排除必空/必机身格）；normal：机头概率最大的格（并列随机）；
  - hard/lunatic/exact/worst：走"期望步数推演引擎" `hardCore`；
- **期望步数推演引擎**：对每个候选格计算"先攻它、再按贪心策略收尾"的步数，取最小。
  性能手段：等价格去重（信念上取值列相同的格子期望严格相等，只需评估代表格）、
  共享真相采样、逐级精化（successive halving，防小样本"胜者诅咒"）、
  信念子样本上限 `cap`。预算见 `THINK`。
- **候选格必要条件**（最优策略的必要条件）：每次进攻须满足
  ① 进攻后剩余组合数减少（该格取值列在信念中不唯一），或 ② 该格是机头所在格。
  即排除 必空格（cover===0）与 必机身格（cover===total && prob===0）；
  伪装模式下"全被覆盖且含机头可能"的新格是复查的必要铺垫，保留。
- **LUNATIC**：AI 无真实布阵（`boards[1]` 为空），仅维护与已给回答自洽的信念
  `ansArr/ansCount`；玩家每次攻击，AI 对每个可显示值（经典 0/1/2；伪装首击 0/1、
  复查 2/3）推演"显示它之后玩家贪心收尾所需的**最短步数**"（对剩余可能真相取
  最好情况），选使**最短步数最长**的值显示——即便玩家运气最好也要花很多步
  （并列时偏向泄露少的值）。结算时 `lunaticReveal` 从自洽组合中随机展示一个布阵。
- **AI 永不读 `boards[0]`**（玩家真实布阵）——这是硬约束，修改时请保持。

### 4.2 人机对战四种难度（aiLevel）

人机对战的难度由 `aiLevel` 决定，四种难度**都不偷看玩家布阵**
（只依赖攻击反馈 `guesses[1]` 推理；信念过滤见 4.1 的 syncAtk/atkObs）。

| 难度 | 决策方式（经典规则） | 决策方式（伪装规则） | 实测强度* |
|---|---|---|---|
| **EASY** | **从未确定的格子中随机选一个攻击**——"未确定" = 该格取值列在信念中不唯一（0/1 混合或 1/2 混合）；必空格（开局即 4 角）与必机身格进攻必无收益，跳过 | 同一"未确定"语义：新格需非必空且非必机身，复查格需仍可能是机头 | 经典 ~16 步 / 伪装 ~16 步 |
| **NORMAL** | 每步严格选**当前机头概率最大**的格子（并列随机），剔除必空格 | 同为概率贪心，但复查格的优先度打 0.65 折（`RECHECK_W`，低价值复查让位于探索），并剔除必空/必机身格与机头概率≈0 的复查格 | 经典 ~14 步 / 伪装 ~16 步 |
| **HARD** | 期望步数推演引擎（见 4.1 `hardCore`）：对每个候选格推演"先攻它、再贪心收尾"的**平均步数**，选期望最小的格（等价组去重 + 逐级精化防噪声） | 同一引擎的伪装语义版本（复查格按已揭示语义过滤与推演） | 经典 ~15 步 / 伪装 ~15 步 |
| **LUNATIC** | 攻击用 HARD 策略；**自己不布置真实飞机**，玩家每次攻击时对每个可显示值推演"显示它之后玩家收尾所需的**最短步数**"（对剩余真相取最好情况），选使**最短步数最长**的值显示——即便玩家运气最好也要花很多步；回答永不自相矛盾，结算时随机展示一个与全部回答一致的布阵 | 同左，可显示值为首击 0/1、复查 2/3 | 经典 ~16 步 / 伪装 ~15 步（另有回答误导） |

\* 完整对局平均步数（越小越强），n=6~10 局的采样值，会随参数与样本波动。
伪装模式各档差距天然小于经典模式（首击 1 信息量弱、每机头需两步确认）。

补充说明：

- **思考时间**：EASY/NORMAL 计算量趋近于零，仅保留 400/600ms 的节奏延时；
  HARD/LUNATIC 仅有 30ms 的调度延时，**实际思考时间 = 期望步数推演的真实计算耗时**，
  随信念收缩自动变快（开局约几十至几百毫秒，越到后盘越快）。
- **伪装模式差异**：HARD/LUNATIC 在伪装规则下使用同一引擎的伪装语义
  （首击观察 1 = "≥1"，复查观察 2/3 = 确认机头/真机身；确认机头的观察会真正
  压缩信念——这是复查价值的来源）。
- **检定页（aicheck.html）的策略与本表对应**：贪心策略 = NORMAL 的决策逻辑；
  期望计算 = HARD 的高精度不限时版（`THINK.exact`）；兜底策略 = 对真相取
  **最坏步数**的 minimax 变体（`THINK.worst`）。

### 4.3 检定页策略与规则语义（aicheck.html）

- 三种策略：贪心（normal）/ 期望计算（exact，不限时高精度）/ 兜底（worst，
  对真相取最坏步数的 minimax）。
- 伪装规则下玩家作答语义：首次询问打中飞机只能答 1（机头伪装）；
  对已答 1 的格子 AI 会复查，此时答 2（机头）或"确认真机身"（内部值 3）。
- 预填面板可在开局前构造任意局面（含矛盾局面，用于测试"宣布无解"）。

## 5. 已知限制与注意事项

- **自定义机队不支持人机对战**（按需求约定禁用；引擎本身可用，若要放开需评估组合规模）。
- **组合上限 400 万**（`MAX_COMBOS`）：飞机画得越小组合越多（呈立方级），超限会报错，
  只能玩双人对战。经典机队 109,192 种；三架满 5×5 块约 1,280 种。
- **性能**：组合空间 ≤ 40 万时自动预建取值快表（快），更大时退回按需读取（慢但可行）。
- **旋转对称去重**：自定义形状可能旋转对称，摆法枚举按"棋盘占格 + 机头位置"去重，
  缺一不可（只按占格去重会把机头朝向不同的摆法错误合并）。
- **伪装模式信念细化**：复查揭示必须触发重新过滤（见 4.1 的 atkObs 说明），
  历史上曾因"每格只处理一次"导致确认机头不压缩信念、矛盾也不触发无解。
- **加载顺序**：ai.js 必须在 game.js 之前（index.html）或提供垫片（aicheck.html）。
- **联机对战**：依赖浏览器 WebRTC 打洞与 PeerJS 公共信令服务器，少数严格
  NAT/公司网络可能连不上（换网络可解）；对战中断线本局作废，不做自动重连续局；
  房间码即门钥匙，只发给想邀请的人。

  编译型小服务器曾触发 Defender 误报，直接双击 HTML 游玩不受影响。
